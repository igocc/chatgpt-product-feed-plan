01

先决定接入路径与首期范围

目标是让 ChatGPT 获取准确的商品目录。自建系统负责数据与投递，OpenAI 负责准入、接收与产品展示。

本交付是实施方案，尚未建设或投递真实 Feed。 未核验企业直连资格，也未读取生产店铺。空白资料应在受控环境补齐，不在公开网页输入。
路径适用情形动作与边界
Shopify 原生分发已在 Shopify 销售，主要诉求是商品被 ChatGPT 发现先核验 Catalog 资格和渠道设置。原生集成不等于获准开通另一条独立直连。[S1] [S9]
自建直接 Feed多来源目录、独立数据治理或有明确的直连接入诉求建设独立数据流水线，并向 OpenAI 申请。系统就绪不替代准入批准。[S2]
第三方分发希望采购服务而非自行运维要求供应商提供实际投递权限、回执和撤回能力证明，不以模板支持代替接入证据。

建议的首期合同

单一商家、单一数据源，面向美国市场、英语内容和 USD，先做商品发现与站外落地页。标准文件上传当前以美国为目标，其他国家和币种需要 OpenAI 确认。此处是建议范围，不能替代商家的业务确认。[S4]

首期不建设购物 Agent、支付、订单处理、广告 Feed 或全渠道分发。后续平台可复用内部目录，但每个平台的权限、格式与市场范围分别验收。文件规范里的 checkout 字段不能自动开启结账。

G0 必须确认：直连的业务价值、目标店铺与域名、商品主数据来源、原生与直连的覆盖关系、上线负责人。若原生分发已经满足需求，可以停在数据审计与完善阶段。

02

审批、候补与「白名单」机制

官方公开的是合作伙伴准入；内部如何按商家、域名、账号或网络授权，并未完整公开。

已确认

提交申请 ≠ 已获批

直接 Feed 接入目前面向获批合作伙伴。官方商家页说明已申请者进入候补名单。[S1] [S2]

未公开

不是已知的 IP 白名单

不能断言按 IP 开通；最低 GMV、最低 SKU、评分权重和审批时限均未在所查官方材料中公布。

  1. 申请前：资料与样例。 业务负责人复核申请表；技术负责人如实声明 Feed 准备状态。
  2. 提交：保存回执。 从 OpenAI 官方商家入口 提交，记录日期、申请主体、域名和联系人。候补状态保持 WAITLISTED。
  3. 平台沟通：补齐接入合同。 仅以 OpenAI 明确批准的主体、域名、市场和方式作为实施依据；补充材料与样例按平台要求提供。
  4. 联调：先提交小样。 使用分配的投递通道，保存可获得的接收、拒绝和纠错证据，确认如何识别处理完成。
  5. 生产：受控放量。 G2 平台验收通过后才能开放自动生产投递。任何展示或排名均不能由提交成功推导。

正式申请表收集：联系人姓名、职务、LinkedIn、工作邮箱，公司名称、总部国家、官网、主要类别、唯一 SKU 规模、接入意向、Feed 准备情况与补充说明。它们是资料项，不是公开的通过阈值。[S1]

04

商品数据合同：先文件，后 API

采用独立内部目录模型，再分别编码文件和 API；两种外部结构不能直接互传。

文件发现 Feed 的基础映射

下表概括首期字段；完整的长度、枚举、条件与可选字段以 S4 为准。数据输出单位是一条可购买商品或变体。[S4]

输出字段要求业务来源项目校验
item_id必填店铺＋市场＋变体不可变 ID字符串；不依赖会变化的 SKU 文案或价格
title必填商品标题＋实际变体信息不堆关键词；与页面选中变体一致
description必填事实性商品描述纯文本；缺失时隔离，不让模型补造规格
url必填已选中变体的公开商品 URL可访问、稳定、与市场和币种一致
brand必填商品实际品牌不能把 vendor 未经核验地当品牌
seller_name必填该报价的真实卖家名称与申报主体、店铺页面关系明确
image_url必填变体主图或适用的商品主图直链公开可取；不能链接图片查看页
availability必填市场可售状态映射文件枚举 in_stock / out_of_stock / pre_order / backorder / unknown
price必填常规价格＋约定币种主单位字符串，例如 79.99 USD
group_id变体条件必填同一商品父级稳定 ID必须不同于每个 item_id
listing_has_variations变体条件必填是否有真实选择维度每个变体行设 true
variant_dict变体条件必填selectedOptions，经统一命名选项组合在组内唯一
sale_price可选真实且正在生效的促销价大于零、低于 price、同币种
gtin / mpn可选经核验的商品标识无值则省略；不造码，保留前导零
is_eligible_search可选，项目显式输出条目搜索资格控制false 用于取消资格；不等同瞬时下架

文件与 API 的关键差异

项目文件发现 FeedProducts API
结构与身份平面条目；item_id 标识变体，group_id 分组Product.id ＋ variants[].id 嵌套结构；关联规则须联调确认
金额price 为主单位字符串，例如 79.99 USD；sale_price 为生效中的促销价price.amount 为货币最小单位整数；79.99 USD 对应 7999，而非 79.99
库存文件使用 pre_order；其他状态按 S4 枚举API 文档示例使用 preorder 等状态；不得机械照搬字符串
缺省／删除完整快照有保留窗口，遗漏不是即时删除PATCH 为 upsert；未包含的产品保持不变，不能当成 DELETE
搜索资格可用 is_eligible_search=false 取消资格，待下次处理公开的 API 产品结构未列出同名控制字段；撤回方式必须平台确认

文件与 API 的字段差异依据 S4、S7。内部统一使用 Decimal 金额、ISO 币种、不可变身份和自定义内部库存枚举；编码时按各自合同转换。不得把内部 price=7999 直接写入文件成为 7999 USD。[S4] [S7]

身份与市场规则

建议内部键包含 merchant_id、source_shop、market、source_product_id、source_variant_id。导出 item_id 使用稳定映射，SKU 仅作为业务属性。不同店铺和市场不得互相覆盖；父商品不是可购买变体。GTIN 没有可靠来源就省略。价格、库存、图片与 URL 必须对应同一市场和变体。

促销规则：有有效且高于现价的常规价时，文件写常规价和较低的 sale_price；否则只写真实现价。compareAtPrice 是否可作为常规价必须由业务验证，不能默认视为真实折扣。API 的现售价格与参考价分别映射。

系统架构与交付模块

建议采用单一后端、持久任务队列和两个独立投递适配器。公开 HTML 只承载文档。

Shopify / ERP只读数据源
→
采集与标准目录身份、市场、版本
→
校验与隔离错误单独处理
→
快照 / 增量任务持久化、可重放
→
获批投递通道SFTP / 条件 API
→
结果与对账接收、处理、展示分离
模块建议实现交付标准
源采集器Shopify Admin GraphQL 批量首读；小目录可分页；Webhook 触发后重新读取权威状态完整数据集、源更新时间、分页／批量结束证据；不能把部分下载当全量。[S11]
内部目录PostgreSQL；不可变 ID、市场维度、源版本、Decimal 金额、资格与隔离原因导出可追溯到源记录和规则版本
校验器Python ＋ Pydantic／JSON Schema；业务一致性校验另列错误含 ID、字段、原因、修复责任人；未知字段不能静默上传
快照生成器JSONL＋gzip 起步；稳定文件名、确定性分片、私有对象存储归档逐行检查、计数核对、内容 hash、规范版本与 manifest
任务与事件PostgreSQL 持久任务／outbox，worker 和调度器分别运行事件去重、重试、死信、并发锁、断点和快照水位
SFTP 适配器校验主机指纹；按平台要求覆盖稳定文件／分片集合真实平台投递证据；首次生产写入默认关闭
API 适配器获批后实现；独立序列化器、身份桥、幂等键和速率控制与文件金额、身份、版本覆盖关系验收后启用
管理与监控FastAPI 提供私有状态／重试／暂停入口；审计日志与指标有负责人、有停机开关；不把管理接口暴露到 Pages

建议运行方式：Docker 化 API、worker、scheduler 与托管 PostgreSQL，搭配私有对象存储和 Secret Manager。开发与联调使用相同镜像，生产独立凭证；具体版本在开工时锁定并记录。首期不需要 Kubernetes、向量数据库、LLM 自动写商品事实或浏览器模拟投递。

最小数据表与工件

catalog_items 记录标准目录；source_events 记录源事件；export_runs 记录水位与计数；delivery_jobs 记录待投递和重试；delivery_receipts 记录平台实际结果；eligibility_actions 记录撤回动作。manifest 至少含 export_id、market、source_watermark、schema_hash、条目数、分片及 hash。内部 manifest 不随意放进 SFTP 根目录。

06

同步、投递与撤回流程

先证明目录正确，再证明平台接受；双通道和多市场必须分别解锁。

首次全量

  1. 只读采集全部源记录，确认分页或批量任务完整结束。
  2. 冻结市场、规则版本与源水位；标准化后输出候选、合格、隔离、撤回条目计数。
  3. 生成样例并人工核验。未获批时只做本地与模拟环境验证。
  4. 获批后投递约 100 条样本。样本规模为官方建议，不是最低 SKU 准入门槛。[S3]
  5. 平台反馈清楚后再上首次全量；保留本地可追溯归档与实际回执。

日常更新

文件通道至少每日完整快照；稳定文件名原位更新，分片集合保持稳定。官方建议单分片不超过约 50 万条、目标小于约 500 MB，项目应按实际压缩体积和平台约定再调小；编码为 UTF-8。JSONL gzip 是本方案首选支持格式。[S3]

事件到达后先验证原始 body 的 HMAC，再持久化并入队；按源事件标识去重。Webhook 可能重复或乱序：重读权威源并比较版本，不用旧事件覆盖新数据。每日全量对账修复漏事件。[S12]

API 若已获批，可作为日内增量更新。全量开始时记录水位，暂缓有覆盖风险的并发写入，待快照处理边界明确后重放较新变更；平台未提供可判断处理完成的机制时，先保持单通道，不能宣称已解决写入顺序。[S2] [S7]

撤回与过期：不能只把商品从导出结果删掉

官方文件规则：遗漏商品可能保留至多 14 天。取消搜索资格应在可处理的快照中显式输出 is_eligible_search=false；需要紧急撤回时走平台确认的升级渠道。该标志不承诺即时生效。[S3]

项目保留最近有效的合规记录和 tombstone，让已下架商品在撤回快照中保留稳定 item_id 与必要字段。验证失败的老商品也必须进入明确处置队列：能生成合法取消资格记录则发送，否则触发人工升级；不能静默漏掉并继续展示旧价。缺货用真实 out_of_stock，禁售或停卖用资格撤回，二者不混同。

SFTP 根目录代表目录集合。不要把备份、临时格式或内部 manifest 放入根目录；上传分片避免长暂停，按平台确认的可接受方式完成替换。文件上传完成不代表 OpenAI 已处理完成。[S3]

故障 Runbook

  1. 传输失败：保留 export_id、错误时间和已脱敏错误；检查凭证有效性、网络和平台状态。业务数据不变时重试同一幂等任务。
  2. 平台拒绝：暂停该批次自动放量，依据实际拒绝原因修复字段，只重新投递受影响记录或修复后的完整文件。
  3. 价格或身份错误：立即暂停后续任务；以权威源重建正确记录；采用平台确认的更正／撤回流程，记录影响范围。
  4. 密钥泄漏：撤销并轮换凭证，检查泄漏位置与访问日志；恢复前清理工件并重新测试。不要只删除网页可见内容。
  5. 平台批准撤销或长期未获批：关闭生产投递，保留本地目录校验能力；按平台终止要求处理数据，继续可用的 Shopify 原生路径。
